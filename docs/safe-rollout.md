# 安全上线流程（Expand / Cutover / Contract）

目标：在**旧版本实例仍在提供服务**的滚动发布期间安全完成破坏性模式变更，
任何时刻新旧实例都能正常读写，且可随时回滚。

## 核心原则：先扩展，后收缩

破坏性变更绝不能“一步到位”。拆成三个阶段，阶段之间通过灰度发布与切流衔接：

1. **Expand（扩展，向前兼容）**：只新增结构、不删除/不收紧。
   - 新旧实例同时运行都不会报错。
   - 新版本开始**双写**新旧结构（如有）。
2. **Cutover（切流/回填）**：回填存量数据，把读写切到新结构。
   - 待新版本实例全部就绪、数据追平后执行；此阶段通常模式不变。
3. **Contract（收缩）**：确认没有任何旧实例依赖旧结构后，再删除旧列/旧约束。

因为 Contract 之前旧结构始终保留，所以在任何一步发现问题都可以快速把应用回滚到旧版本，
模式层无需紧急修复。

## 各类变更的具体路径

### 删列 `drop_column`

| 阶段 | 动作 |
| --- | --- |
| expand | 模式不变（NoOp）；应用层先发布“不再读写该列”的版本并灰度 |
| cutover | （无）确认全量实例都已停止使用 |
| contract | 真正 `drop column` |

### 重命名列 `rename_column`

| 阶段 | 动作 |
| --- | --- |
| expand | 新增影子列（新名字，可空），新版本对旧列/新列双写 |
| cutover | 回填旧数据到新列，读切换到新列，停止写旧列 |
| contract | 删除旧列 |

### 改列类型 `alter_column`

| 阶段 | 动作 |
| --- | --- |
| expand | 新增目标类型的影子列 `<col>_new`（可空）并双写 |
| cutover | 回填/转换存量数据，读写切到新列 |
| contract | 删除旧列，再把影子列重命名为正式列名 |

### 加非空约束（无默认值）

| 阶段 | 动作 |
| --- | --- |
| expand | 先加默认值并回填存量行（列仍可空） |
| cutover | 新版本保证不再写空值 |
| contract | 全部实例升级后再加 `NOT NULL` |

### 删表 `drop_table`

**无安全在线路径**：只要还有一个旧实例就会失败。必须先在应用层彻底下线对该表的
所有依赖（功能开关 + 观察期），确认零调用后再安排独立维护窗口删除。引擎对该变更
只给出拒绝（`drop_table`，`staged=false`）。

## 使用引擎落地

```go
// 1) 提交迁移前，先在 CI/预检中运行兼容性检查（也可直接调用）
_, err := eng.Migrate(ctx, "2.0.0")
var rj *migrator.RejectedPlanError
if errors.As(err, &rj) {
    // 打印/阻断发布；rj.Staged 给出阶段定义
}

// 2) 随应用的第一个版本发布执行 expand（只新增、向前兼容）
//    可直接用 MigrateStaged 一次跑完所有阶段；更稳妥的做法是按阶段版本分批执行。
res, _, err := eng.MigrateStaged(ctx, "2.0.0+expand")

// 3) 灰度新版本 -> 双写 -> 回填/切流（cutover 通常是数据/应用动作）

// 4) 全量升级且观察无旧实例后，执行 contract 清理
res, _, err = eng.MigrateStaged(ctx, "2.0.0+contract")
```

> 说明：引擎支持一次性 `MigrateStaged("2.0.0")` 顺序跑完 expand→cutover→contract，
> 适合演示与测试；**真实滚动发布应把 expand 与 contract 分到两次部署中**，
> 中间留出灰度与观察窗口，否则将失去“旧实例仍可用”的意义。

## 回滚策略

- **expand/cutover 阶段出问题**：直接回滚应用即可，旧结构仍在；需要时可用阶段迁移的
  `Down` 撤销新增的影子列。
- **contract 阶段之前**都保留旧结构，因此应用回滚不依赖紧急 DDL。
- 引擎的 `Rollback(target)` 对已应用的阶段版本同样按**逆序**撤销（见
  `cmd/migrator-demo` 输出），可恢复到任一已应用目标版本。

## 上线检查清单

- [ ] 预检：`Migrate` 对目标版本不返回 `RejectedPlanError`，或已按 `Staged` 拆分。
- [ ] expand 与 contract 分属两次部署，中间有灰度与观察期。
- [ ] 双写/回填有对账手段，切流前新老数据一致。
- [ ] 租约参数与迁移规模匹配（见 `config.md`），崩溃接管时间可接受。
- [ ] 明确回滚责任人与路径；contract 在确认零旧实例后才执行。
